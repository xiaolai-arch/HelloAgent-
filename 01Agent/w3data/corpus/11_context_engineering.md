# Context Engineering：Prompt 工程的下一站

## 行业话术的转变

2025 年起，面试话术从 Prompt Engineering 升级为 Context Engineering。区别在于管理对象：Prompt 工程管"一条提示词怎么写"，上下文工程管"整个上下文窗口里放什么"——系统指令、对话历史、检索资料、工具返回、记忆，全都是上下文的一部分。

## 三个核心问题

1. **预算（Budget）**：上下文窗口、注意力质量、成本/延迟三者一起算。窗口再大，注意力对中间信息的利用率也会衰减（context rot，上下文腐烂），塞得越满效果越差，钱也烧得越快。
2. **压缩（Compression）**：历史太长要压缩。优先"可恢复压缩"——保留路径/URL/ID 等可以随时取回原文的引用；摘要是有损压缩，只做兜底。
3. **记忆分层（Memory）**：工作上下文（当前窗口）→ 会话状态（跨轮次）→ 长期记忆（语义/情景/程序性，跨会话）→ 外部知识（RAG 检索）→ 模型参数（训练时写死）。不同层用不同工具管。

## 与 RAG 的关系

从上下文工程的视角看，RAG 不是"外挂一个向量库"，而是"在推理前按需选择最相关的外部上下文，并在有限 token 预算内组织成模型能用的形式"。RAG 的检索 top-k、排序、去重、压缩，本质都是在做上下文的"选材和排版"。

## 面试三句话版本

1. 预算：token、注意力、成本/延迟，三者一起算，不是窗口越大越好。
2. 压缩：优先可恢复压缩（引用可取回），摘要有损只做兜底。
3. 记忆分层：工作上下文、会话状态、长期记忆、外部知识、模型参数，各归各的工具管。
