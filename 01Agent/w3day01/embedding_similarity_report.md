# Embedding 与文本相似度实验报告（W3 Day1）

- 生成时间：2026-10-22 15:24:26
- 语义向量：`BAAI/bge-small-zh-v1.5`（fastembed 本地推理，512 维）
- 词袋对照：HashEmbed 字符 bigram 哈希（512 维，纯 Python）
- 实验文本：11 条 × 3 组（同义改写 / 字面重叠 / 精确词）

## 一、词向量 → 句向量 → 稠密向量表示

| 阶段 | 代表 | 一句话 | 缺陷 |
|---|---|---|---|
| 词向量 | Word2Vec / GloVe | 一个词一个固定向量 | 多义词只有一个表示；没有句级语义 |
| 句向量 | Sentence-BERT | 整句编码成一个向量 | 早期模型对中文/短句较弱 |
| 上下文相关表示 | BERT | 同一个词在不同上下文里向量不同 | 编码慢，需再蒸馏出检索模型 |
| 现代 Embedding | BGE / text-embedding-3 / Jina | 检索优化，配合向量库使用 | 查询与文档必须同模型同版本 |

演进方向始终是一个：**让意思相近的文本在向量空间里更近，并让多义词获得上下文相关的表示。**

## 三、余弦相似度：手算对照

```text
a = [1.0, 0.0, 2.0, 1.0]
b = [1.0, 1.0, 1.0, 0.0]
点积 a·b   = 3.0
|a| = 2.449   |b| = 1.732
cos(a,b) = 3.0 / (2.449×1.732) = 0.707
```

代码 `ragkit.cosine` 对同一对向量返回 0.707，与手算一致。
bge 输出的向量已做 L2 归一化（长度为 1），此时余弦 = 点积；
检索场景几乎都用余弦：它衡量方向一致，不受向量长度影响。

## 五、结论

- **语义向量能把同义改写聚到一起**（分离度 +0.122）："怎么申请退货退款"和"商品退款流程是什么"几乎没有共同字，余弦仍然最高。
- **词袋向量会被字面重叠骗到**（分离度 +0.108）：它只看字符 bigram 重叠，"苹果手机"和"苹果维生素"的字面相似度不低，语义上却毫无关系。
- **精确词是语义向量的弱项**：两个格式相同、取值不同的错误码，在语义空间里
  几乎一样近——区分它们靠 BM25 精确匹配，这正是 Day5 混合检索的动机。
- **机制层面**：任何文本 → 定长向量 → 余弦排序，这套流程不因模型而变；
  换 Embedding 模型只是换了一个"语义坐标系"。
