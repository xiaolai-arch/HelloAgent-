# Agent 四大模式对比

## 1. ReAct（反应式循环）

Thought → Action → Observation 循环，一步一步走、走一步看一步。优点：简单、灵活、可解释（每步都有推理痕迹）；缺点：步数多了误差累积、上下文越滚越长、容易在同一个地方打转。适合：工具不多（几个以内）、路径不确定的探索式任务。这是 Agent 的默认起手式。

## 2. Plan-and-Execute（先规划后执行）

先让模型把任务拆解成完整的步骤清单（Plan），再逐步执行，执行中发现偏差可以重规划（Re-plan）。优点：全局视野，不会走偏太远，执行步骤可以并行；缺点：初始计划质量决定上限，环境变化快时计划容易过时。适合：结构清晰的多步任务（如"调研并写一份报告"），步骤间依赖明确。

## 3. Reflection（反思/自我批判）

生成初稿 → 让模型（或另一个模型）批判性地审查 → 根据批评修改 → 再审，循环到满意为止。优点：显著提升写作、代码类任务质量；缺点：每轮反思都是额外的 token 成本和延迟，容易过度打磨或陷入循环。适合：质量要求高、答案可迭代打磨的任务（写文案、改代码）。变体：Reflexion 把失败的执行结果存成经验，下一轮改进。

## 4. Multi-Agent（多智能体协作）

多个 Agent 各自带角色（规划者/执行者/审查者）或各管一段子任务，通过消息传递协作。优点：分工并行、上下文隔离（每个 Agent 只带自己需要的资料）、可以互相制衡；缺点：通信开销大、错误会级联放大、调试困难——两个 Agent 对话十几轮，谁也说不清哪一步跑偏。适合：任务可以真正切分成独立子任务的场景（多代码库修改、多源调研）。

## 怎么选

| 场景 | 推荐 |
|---|---|
| 工具少、路径探索式 | ReAct |
| 步骤清晰、可预先拆解 | Plan-and-Execute |
| 质量可迭代打磨 | Reflection |
| 子任务天然独立、可并行 | Multi-Agent |

原则：从最简单的 ReAct 开始，确认单 Agent 解决不了再加模式。Anthropic 的工程建议：能一个 Agent 干的活，不要上多 Agent——复杂度是成本，协作是风险。
