# Embedding：把文本变成向量

## 演进脉络

词向量（Word2Vec、GloVe）→ 句向量（Sentence-BERT）→ 上下文相关表示（BERT）→ 现代 Embedding 模型（BGE、text-embedding-3、Jina、Voyage）。演进方向始终是一个：让"意思相近的文本"在向量空间里离得更近，并且一个词在不同上下文里有不同的向量（解决多义词问题）。

Embedding 模型本质上是"把变长文本压缩成定长向量"的编码器：输入一段文本，输出一个固定维度（如 512、768、1024、1536 维）的浮点向量，这个向量就是文本的"语义坐标"。

## 相似度：余弦相似度

衡量两个向量方向是否一致：

```text
cos(a, b) = (a·b) / (|a| × |b|)
```

取值 [-1, 1]，越大越相似。现代 Embedding 模型输出的向量通常已做 L2 归一化（长度为 1），此时余弦相似度退化为点积，省一次除法。注意区分：欧氏距离衡量"绝对远近"，余弦衡量"方向一致"，文本检索几乎都用余弦。

## 关键性质与坑

1. **查询和文档必须用同一个模型、同一个版本**编码，否则两者根本不在同一个语义空间，相似度没有意义。
2. **语义匹配 ≠ 关键词匹配**："如何退货"和"退款流程说明"几乎没有共同字，语义向量也能给高分；但错误码 `ERR_40231`、产品型号这类精确词，语义模型反而容易混淆——这正是需要 BM25 混合检索的原因。
3. **维度越高表达能力越强**，但存储和检索成本也越高；中文任务优先看 C-MTEB 榜单和业务实测。
4. **最大输入长度有限**（常见 512 token），超长文本要先切分再分别编码。

## 怎么用

调用 Embedding API（或本地模型）把文档库全部编码存入向量库；查询时只把用户问题编码一次，然后和库内所有向量算余弦、取 top-k。向量化是离线一次性成本，查询侧只需编码一个短句，延迟很低。
