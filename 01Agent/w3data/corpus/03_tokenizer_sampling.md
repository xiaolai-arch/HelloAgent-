# Tokenizer、采样参数与上下文窗口

## Tokenizer：文本怎么变成数字

模型不认识字符串，只认识 token ID。Tokenizer 负责把文本切成 token 并映射成整数序列，主流方案是子词切分（BPE，Byte Pair Encoding）：从字节级开始，反复合并语料中出现频率最高的相邻对，得到一个介于"词"和"字符"之间的切分粒度。英文常见经验值是 1 token ≈ 0.75 个单词；中文常见经验值是 1 个汉字 ≈ 1~2 个 token，取决于词表对中文的优化程度。

OpenAI 的 tiktoken 库可以在本地精确统计任意文本在 GPT 系列编码（如 o200k_base、cl100k_base）下的 token 数。API 响应中的 usage 字段（prompt_tokens / completion_tokens）就是对输入和输出分别计数的结果，直接决定调用费用。

## 采样：模型怎么挑下一个 token

语言模型每一步输出的是词表上的概率分布，采样策略决定"怎么从分布里挑一个"：

- **贪心（temperature→0）**：永远选概率最大的 token。输出确定、可复现，适合抽取、分类、代码补全这类要稳定的任务。
- **温度（temperature）**：给 logits 除以 T 再 softmax。T 越小分布越尖（输出越确定），T 越大分布越平（低概率 token 被选中的机会变大，输出越发散、越随机）。温度越高输出越随机的原因就在这里：它改的是分布的形状。
- **Top-p（核采样）**：只在累计概率达到 p（如 0.9）的最小 token 集合里采样，动态截断长尾。
- **Top-K**：只在概率最高的 K 个 token 里采样，截断窗口固定。

工程默认：事实问答 temperature 取 0~0.3，创意写作用 0.7~1.0。

## 上下文窗口（Context Window）

上下文窗口是模型一次能处理的最大 token 数，输入（system + 历史 + 检索资料）和输出共享这个预算。窗口之外的内容模型完全看不见——不是"记不清"，是根本没进模型。长对话、RAG 检索资料、工具返回结果都要计入这个预算，所以才有上下文工程：在有限预算内决定"什么进来、怎么排、留多少余量"。
