## 一、四指标各自在评什么

| 指标 | 层 | 问题 | 低分意味着 |
|---|---|---|---|
| Faithfulness | 生成 | 答案的每条论断都被上下文支持吗 | 模型在编造/超出资料发挥 |
| Answer Relevancy | 生成 | 答案回答了问题吗 | 答非所问 |
| Context Precision | 检索 | 相关资料排在前面吗（AP） | 排序差，噪声挤占注意力 |
| Context Recall | 检索 | 标准答案所需信息资料里齐吗 | 检索漏了，生成再好也白搭 |

排查顺序永远是：Context Recall → Context Precision → Faithfulness，
先检索后生成，锅才能甩对位置。

## 四、LLM-as-judge 的坑（本次实测观察到的）

1. **judge 与生成同模型**：自我偏好风险；生产应换更强的模型当 judge，
   并用人工标注的小集合校准一致率。
2. **弃权回答被误伤（Q13(faith=0.667)、Q14(faith=0.0)）**："根据现有资料无法确定"是正确行为，
   但 judge 把"资料中没有提到 X"这类**元陈述**当成了需要资料支持的
   论断去核对，判了不支持 → faithfulness 虚低。修正方向：rubric 里
   显式豁免弃权表述，或对弃权回答走单独的评估通道。
3. **rubric 措辞敏感**：本次在 relevancy 里补了一句"正确弃权算 5 分"，
   否则不可回答题的"无法确定"会被 judge 误判为答非所问——
   这既说明 judge 的评分是 prompt 的函数，也说明弃权必须被显式建模。
4. **拆论断的粒度不稳定**：faithfulness 的论断数量随题波动，
   一条长论断被拆成两条后，部分支持就会拉低分数。
5. **Context Precision 的 AP 公式**：相关块排第 1 记 1.0、第 5 记 0.27，
   排序位置的影响被显式计入——这正是"重排为什么值得做"的量化理由。

## 五、结论

1. **分层定位**：rule Recall@k=0.923、Context Recall=0.845 说明检索覆盖是基本够用；Faithfulness=0.964 说明生成侧
   的 grounding 约束基本生效（带引用 + 弃权条款）。
2. **改进迭代**：top5→top3，Context Precision 0.827→0.833，Faithfulness 0.964→0.956，Recall 0.845→0.784——用数据决定"候选该多宽"，而不是拍脑袋。
3. **指标要一起看**：任何单一指标都能被刷高（少给上下文必涨 precision），
   四个指标 + 弃权率构成一张互相制衡的网。
