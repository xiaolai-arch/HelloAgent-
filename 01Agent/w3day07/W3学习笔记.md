## 一、RAG 的定位：一句话与三个追问

> **RAG = 开卷考试：先从外部知识库找到相关资料，把资料放进上下文，让模型带着证据回答。**

三个追问（自测用）：

1. 模型缺的是什么？——知识（→RAG）、推理（→CoT/工具）、权限（→检索层 ACL）、
   实时性（→索引更新）。先诊断再上 RAG。
2. 什么时候不用 RAG？——库小而静态可整体入上下文、结构化数据用 SQL、
   延迟敏感。长上下文模型也不能完全替代：窗口再大，注意力预算和成本有限。
3. RAG 失败有几种死法？——离线（资料没进来/切散了）、在线（没召回/排序差/
   上下文太吵）、生成（不忠实/漏引用）。分层排查，别一上来就换 embedding。

## 二、两条流水线（必须能白板画）

```text
离线索引：文档 → 解析 → 清洗 → 切分 → 元数据 → 向量化 → 向量索引
                                            ↘ BM25 倒排索引
在线查询：问题 → (改写) → 召回[Dense + Sparse] → 融合(RRF) → 重排
                → 上下文打包(去重/排序/预算/编号) → 生成 → 引用
```

本周实验对应的环节：切分（day4）、向量化与库（day1/2）、召回+融合+重排
（day5）、打包+生成（day3）、评估（day6）。

## 三、切分：五个决策点

1. **策略**：固定长度（快但拦腰切）/ 递归字符（默认推荐）/ 语义切分
   （贴主题边界但要逐句编码）/ 结构感知（按标题/代码块）。
2. **大小**：200~800 token 起步；实验实证"太小明确有害"（碎块凑不齐相关性）。
3. **重叠**：10%~20%；它是硬切的止血带——实证 overlap 保 Recall 但稀释 MRR。
4. **完整性**：表格、代码、公式不硬切。
5. **元数据**：每个 chunk 带 title/section/source；检索可过滤、引用可追溯。

进阶（知道即可）：父子块（小块检索、大块喂模型）解决"检索粒度 vs 生成粒度"
冲突；Contextual Retrieval 给 chunk 预置文档背景再索引。

## 四、检索：漏斗是标准形态

```text
宽召回（双路各 top20）→ RRF 融合 → 重排（cross-encoder）→ top5 进上下文
```

| 层 | 用什么 | 为什么 |
|---|---|---|
| Dense | bge/text-embedding-3 | 同义改写、跨表述 |
| Sparse | BM25（k1=1.5, b=0.75） | 错误码/型号/人名精确匹配，可解释 |
| 融合 | RRF：score=Σ1/(60+rank) | 只用排名（无量纲），两路分数不可加 |
| 重排 | cross-encoder 逐对打分 | query 和 chunk 互相看见，MRR 显著提升 |
| 打包 | 去重、编号、`<context>` 标签、控制预算 | 防注入、防"lost in the middle" |

实验锚点数字（详见 w3day05 报告）：混合使 Recall@5 0.867→0.933，
重排使 MRR 0.639→0.717，代价约 3s/题（20 候选，本地 int8 模型）。

## 五、生成：Grounding 三件套

1. **带引用**：每个关键结论标 [编号]，编号映射回文档/章节。
2. **允许弃权**："资料不足明确说不知道"必须写进 prompt 并纳入评估
   （实测弃权率 100% 可达成，但 judge 会误伤弃权——见 day6）。
3. **标签隔离**：资料用 `<context>` 包起来，防资料里的指令被当成系统指令。

## 六、评估：一张分层指标表

| 层 | 指标 | 低分意味着 | 修哪里 |
|---|---|---|---|
| 检索 | Recall@k / HitRate | 相关 chunk 没进 top-k | 切分、混合检索、调大 k |
| 检索 | MRR / Context Precision | 排序差 | Rerank、RRF 调参 |
| 生成 | Faithfulness | 编造/超出资料 | 强化 grounding、弃权条款 |
| 生成 | Answer Relevancy | 答非所问 | prompt、上下文太吵 |
| 端到端 | 弃权准确率 | 该弃权没弃权/不该弃弃了 | 弃权条款 + 不可回答题入测 |

排查顺序：**Context Recall → Context Precision → Faithfulness**（先检索后生成）。
黄金集 20~30 条起步，必须含：可回答、不可回答、多跳、精确词四类。

## 七、与前后周的衔接

- **W2 → W3**：Context Engineering 的"预算/选材"视角——RAG 的 top-k、重排、
  去重本质是上下文的选材与排版；W2 的弃权/引用条款在这里变成 prompt 常量。
- **W3 → W4**：RAG 本身可以被 Agent 化——把"检索"注册成一个工具，让 ReAct
  循环决定"查不查、查什么、查几轮"（Agentic RAG 的雏形，w4day01 的
  search_knowledge 工具就是这条路）。
- **带进 W5/阶段二的问题**：多跳信息被切散（父子块待验证）、LLM-judge 校准、
  网关差异的工程兜底。

## 八、术语速查（本周新增）

| 术语 | 一句话 |
|---|---|
| Embedding | 文本→定长向量，语义坐标 |
| 余弦相似度 | 方向一致性；L2 归一化后=点积 |
| ANN / HNSW | 近似最近邻索引，用极小召回损失换数量级提速 |
| Chunk / overlap | 检索单元 / 跨边界信息的双份拷贝 |
| Dense / Sparse | 语义向量检索 / BM25 词频检索 |
| RRF | 按排名倒数融合多路结果，k 常取 60 |
| Cross-encoder | (query, chunk) 成对编码的重排模型 |
| Recall@k / MRR | 相关块进没进前 k / 最好的块排多前 |
| Faithfulness / Context Precision / Context Recall | 忠实度 / 排序质量 / 覆盖度 |
| Contextual Retrieval | 给 chunk 预置文档背景再索引 |
| lost in the middle | 上下文中间位置的信息利用率最差 |
