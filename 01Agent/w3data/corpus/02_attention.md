# 注意力机制：Q、K、V 与多头

## Scaled Dot-Product Attention

注意力机制的核心公式：

```text
Attention(Q, K, V) = softmax(Q·K^T / sqrt(d_k)) · V
```

三个角色：

- **Q（Query，查询）**：当前位置"我想找什么信息"。
- **K（Key，键）**：每个位置"我能提供什么信息"的索引。
- **V（Value，值）**：每个位置实际携带的内容。

计算流程分四步：第一步，Q 和 K 做点积，得到每对位置之间的原始相关性分数；第二步，除以 sqrt(d_k)（K 的维度开根号）做缩放——维度越大点积方差越大，不缩放会把 softmax 推入饱和区，梯度消失；第三步，按行做 softmax，把分数归一化成注意力权重（每行之和为 1）；第四步，用权重对 V 加权求和，得到该位置的输出——它本质上是对全序列信息的"按相关性加权的读取"。

## Multi-Head Attention（多头注意力）

多头不是算一次注意力，而是把 d_model 维拆成 h 个头（原始论文 h=8，每头 d_k=d_model/h=64），每个头独立做一遍上面的注意力，最后把各头输出拼接再过一个线性层。

为什么要多头：单头注意力只有一个"相关性视角"，多头让不同头各学一种关系——有的头盯语法依存，有的头盯指代消解，有的头盯相邻位置。类比：一组专家各自带着不同问题清单（Q）去问同一篇文档（K、V），最后把笔记汇总。

手算一个小例子：设两个 token 的 Q1=[1,0]、K2=[1,1]、V2=[2,3]，d_k=2。分数 = Q1·K2 = 1；缩放 = 1/sqrt(2)≈0.71；单 token 时 softmax 后权重就是 1；输出 = 1×V2 = [2,3]。真实模型就是把这个过程对几万个 token × 几十层并行做几亿次。

## 复杂度

自注意力的计算量和显存都是 O(n²·d)：n 是序列长度。序列翻倍，计算量翻四倍——这是长上下文昂贵的根本原因，也是各种稀疏注意力、滑动窗口注意力、FlashAttention（不省计算量、省显存读写）要解决的问题。
